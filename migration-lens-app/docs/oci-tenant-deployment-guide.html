Overview

This guide deploys the demo as a static web application packaged in a container. The default target is a private OCI Container Instance behind a private OCI Load Balancer. Oracle describes OCI Container Instances as serverless compute for running containers without managing servers, and this prototype fits that model because it only needs one static web container.

Prerequisites

  • OCI CLI configured for tenant phieng2345, with a profile that can inspect IAM, Networking, Load Balancer, Container Instances, OCIR, Cloud Guard, Security Zones, and Vulnerability Scanning.
  • Docker and Colima available locally for the image build. The local demo already uses migration-lens-app:local and port 8080.
  • GitHub CLI authenticated to https://github.com/phileng for repository creation and push.
  • An OCI auth token for Docker login to OCIR. Do not paste the token into this document, shell history, GitHub, image layers, or the React bundle.
  • A private subnet for the Container Instance and private Load Balancer, plus NSGs that allow only required traffic.

Build, create repository, tag, push

3. Prepare Container Instance JSON

OCI CLI accepts complex JSON for Container Instance creation. Generate the template with the CLI, then fill the required fields rather than hand-writing the full payload from memory.

Generate and apply create JSON
mkdir -p deploy/oci/generated
oci container-instances container-instance create \
  --generate-full-command-json-input \
  > deploy/oci/generated/container-instance-create.json

# Edit deploy/oci/generated/container-instance-create.json:
# - compartmentId: $COMPARTMENT_OCID
# - availabilityDomain: selected AD name
# - shape: CI.Standard.E4.Flex or approved equivalent
# - shapeConfig: small CPU/memory for static app
# - containers[0].imageUrl: $IMAGE_NAME
# - containers[0].displayName: migration-lens
# - containers[0].ports/containerPort: 8080
# - vnics[0].subnetId: $PRIVATE_SUBNET_OCID
# - vnics[0].isPublicIpAssigned: false
# - vnics[0].nsgIds: [$APP_NSG_OCID]
# - containerRestartPolicy: ALWAYS
# - freeformTags/definedTags: owner, env, data-classification, cost-center

oci container-instances container-instance create \
  --from-json file://deploy/oci/generated/container-instance-create.json \
  --wait-for-state SUCCEEDED \
  --max-wait-seconds 1800
4. Create private Load Balancer path
Private Load Balancer, backend set, backend, listener
oci lb load-balancer create \
  --compartment-id "$COMPARTMENT_OCID" \
  --display-name "${APP_NAME}-private-lb" \
  --shape-name flexible \
  --shape-details '{"minimumBandwidthInMbps":10,"maximumBandwidthInMbps":10}' \
  --subnet-ids "[\"$LB_SUBNET_OCID_1\",\"$LB_SUBNET_OCID_2\"]" \
  --is-private true \
  --is-delete-protection-enabled true \
  --is-request-id-enabled true \
  --request-id-header X-Request-Id \
  --wait-for-state SUCCEEDED

export LOAD_BALANCER_OCID="<from-create-response>"
export CONTAINER_PRIVATE_IP="<container-instance-vnic-private-ip>"

oci lb backend-set create \
  --load-balancer-id "$LOAD_BALANCER_OCID" \
  --name migration_lens_backend \
  --policy LEAST_CONNECTIONS \
  --health-checker-protocol HTTP \
  --health-checker-port 8080 \
  --health-checker-url-path /healthz \
  --health-checker-return-code 200 \
  --health-checker-interval-in-ms 10000 \
  --health-checker-timeout-in-ms 3000 \
  --health-checker-retries 3 \
  --wait-for-state SUCCEEDED

oci lb backend create \
  --load-balancer-id "$LOAD_BALANCER_OCID" \
  --backend-set-name migration_lens_backend \
  --ip-address "$CONTAINER_PRIVATE_IP" \
  --port 8080 \
  --weight 1 \
  --wait-for-state SUCCEEDED

oci lb listener create \
  --load-balancer-id "$LOAD_BALANCER_OCID" \
  --name migration_lens_http_private \
  --default-backend-set-name migration_lens_backend \
  --protocol HTTP \
  --port 80 \
  --wait-for-state SUCCEEDED
For internet-facing review, terminate TLS and WAF at an approved front door instead of exposing the Container Instance directly. This runbook defaults to private access.

Appendix: How the Prototype Works in This Deployment

The prototype is a static React/Vite application. The source code uses React state and an in-code representative mapping dataset to compare OCI, AWS, Azure, and GCP service categories. The deployment does not add an application backend.

Build and runtime model

  • npm run build runs Vite and produces the static dist/ bundle.
  • The Dockerfile builds the app in a Node stage and copies dist/ into an unprivileged NGINX runtime image.
  • NGINX listens on 8080, matching the local Docker demo and OCI backend port.
  • The container serves static files only; there is no server-side API, database, session store, or user-specific state.

Health and routing behavior

  • /healthz is served directly by NGINX and returns ok, so Load Balancer and Container Instance health checks do not depend on React initialization.
  • The SPA fallback rule try_files $uri $uri/ /index.html sends unknown browser paths back to the React entrypoint.
  • Static asset responses include browser cache headers for CSS, JS, images, and fonts.

Browser-side prototype behavior

  • The app starts with the Route layer selected and lets reviewers filter categories, search services, select architecture layers, inspect migration notes, and view gap counters.
  • All provider comparison data is bundled into the JavaScript artifact. Treat it as representative seed data, not an authoritative all-services catalog.
  • Because the UI runs entirely in the browser, the deployed container can be replaced safely by publishing a new immutable OCIR image tag and updating the Container Instance.

Security implications

  • Do not place secrets, auth tokens, private OCIDs, or internal-only data in React source, build artifacts, environment variables, GitHub files, or Docker layers.
  • The static app should be reviewed as public-to-internal documentation unless a data owner explicitly approves stronger classification.
  • Operational evidence lives at the OCI layers: Load Balancer health, Container Instance lifecycle state, OCIR image scan results, Cloud Guard findings, and approved network rules.
